# Тестовые сценарии

Три уровня проверки:

| Уровень | Как запустить | Что проверяет |
|---|---|---|
| Автотесты (24) | `docker build --target test --build-context mocks=./mocks -t creditflow-test backend && docker run --rm creditflow-test` | Модель решения, автомат статусов, API-сценарии на SQLite с синхронным конвейером |
| Сквозная проверка стенда | `python scripts/e2e_smoke.py` | Настоящий стенд: PostgreSQL, воркер, nginx, моки |
| Ручные сценарии | ниже | Пользовательский опыт в веб-интерфейсе |

Перед ручной проверкой: `docker compose up --build`, адрес http://localhost:8080. Для чистого прогона: `docker compose down -v && docker compose up --build`.

## TC-01. Автоодобрение и путь до выдачи денег

**Роль:** клиент `bakery@demo.ru`.

| # | Шаг | Ожидаемый результат |

## TC-02. Встречное предложение

**Роль:** клиент `smirnov@demo.ru`. Запрос: «Экспресс-кредит», 5 000 000, 24 мес.

**Ожидается:** статус **«Есть предложение»**, два варианта: «меньшая сумма» (≈ 2,3 млн под 21,5%) и «Льготный кредит МСП» (≈ 2,35 млн под 18,25%). В «Что повлияло» 🔴 просрочка и долговая нагрузка. Выбор варианта и «Принять» → «Подписание».

## TC-06. Подтверждение выручки выпиской

**Роль:** `bakery@demo.ru`. Новая заявка «Экспресс» 1 млн; на шаге «Финансы» указать выручку **120 000 000** (ФНС: 48 млн).

**Ожидается:** «Нужна информация»: расхождение с данными ФНС → загрузить [`testdata/bank_statement_sample.csv`](../testdata/bank_statement_sample.csv) → «распознано N операций за 12 мес.» → отправить → заявка проходит оценку на подтверждённой выручке.

## TC-09. Отказоустойчивость

| # | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | `curl -X POST localhost:8090/admin/chaos -H "Content-Type: application/json" -d '{"source":"bki","failure_rate":1}'` | Сбой БКИ включён |
| 2 | Подать заявку любым клиентом | После 3 попыток заявка уходит в **«У специалиста»**, в карточке аналитика «Источник данных недоступен: Бюро кредитных историй» |
| 3 | `docker compose restart api` во время работы | Интерфейс восстанавливается без перезапуска `web` |
| 4 | `docker compose up -d --scale worker=3` | Задачи распределяются без двойной обработки |
| 5 | Вернуть `failure_rate: 0` | Новые заявки снова решаются автоматически |

## TC-10. Безопасность и доступ

| Проверка | Ожидается |
|---|---|
| Клиент открывает URL чужой заявки | 404 |
| Клиент вызывает `/api/v1/bank/applications` | 403 |
| Запрос без токена | 401 |
| Регистрация с ИНН `7720123450` (неверная контрольная сумма) | 422 «Некорректный ИНН» |
| Загрузка `.exe` | 415 |
| Аналитик пытается решить заявку на комитете | 403 |
| Переход статуса в обход автомата (например, повторный `accept-offer`) | 409 |
